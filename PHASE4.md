# Phase 4 — generation evaluation

The L2 section of `rag-evals.md` is a metric catalog. This implementation uses its formulas where specified and makes reference labels explicit. `expected_answer` may describe behavior, so only `exact_match_references` count as deterministic gold answers. The judge consumes the question, recorded retrieved chunks, generated answer, citations, and independent labels. The retrieved chunks are **not verified to be the exact context shown to the bot**. Every judge score is provisional until reviewed by a person; a missing label, malformed response, or judge error never becomes a quality score of zero.

## Judge contract

The dashboard's **Approved judge gateway** sends one JSON POST per applicable metric and case. It includes `metric`, `prompt_version`, `rubric_version`, rubric instructions, question, `retrieved_evidence` with IDs and text, generated answer, citations, reference points, gold answers, answerability, and trap labels. The caller adds configured `model` and `model_version`. The gateway must return the same model and version, prompt and rubric versions, and a nonempty `items` array. Every item has `text`, `verdict`, `evidence_ids`, `supporting_evidence`, and `explanation`; citation items also have `citation_id`. Answer relevance additionally returns `generated_questions`, `question_embedding`, `generated_question_embeddings`, and `embedding_model` with version. Local code recomputes every score and rejects invented evidence quotes, unknown chunk IDs, invalid verdicts, invalid vectors, or mismatched versions. The raw response and derived score are both retained in the in-session trace.

The **OpenAI (.env)** path reads only `OPENAI_API_KEY` and `OPENAI_MODEL`; `.env` is Git-ignored. It uses the Responses API with a strict JSON schema and `store=false`. Answer relevance additionally uses the embeddings API with `text-embedding-3-small`; local code computes cosine similarity. The dashboard requires explicit approval before sending the selected question, retrieved evidence, answer, and references to OpenAI. The earlier attempted live smoke call was rejected by automatic approval review for lack of explicit authorization for that payload, so only mocked API contract tests have run. The configured key and model do not by themselves authorize sharing real Confluence content.

For real content, confirm that the provider may receive this data class. The token is not written into run artifacts. Live run artifacts redact answer, reference, retrieved text, and judge content by default. The result retains safe score metadata; detailed traces remain in the current session. A human reviewer can accept or reject a scored judgment with an explanation. Only an accepted judgment gets an `effective_score`; a rejected one has none. These review records are distinct from automated validation tests. A production judge needs independent human labels and agreement checks before its scores become decision evidence.

## Validation and limits

Run `python3 -m pytest -q` and inspect the app's case trace. The synthetic fixture judge is named `synthetic-human-labels`; it is deliberately not presented as an LLM result. The gateway adapter has no approved production provider configured. Citation precision depends on sentence-to-citation attribution supplied by the judge because the bot response currently carries a flat citation list. Exact generation context, real bot integration, and independently reviewed real labels remain unavailable.
